1 · 这是什么

交付物DSH 挂载层里的「副将活动面板」——由 dsh-plugin 这套 bundle patch 挂进 DSH，本身不改套件本体
怎么挂的dsh-plugin/build-patch.mjs 渲染出 dsh-plugin/cordis.patch.yml，把面板 client entry 与 GET /dsh-deputy/panel.json 注册进 DSH
数据来源宿主侧 lib/panel-data.js 从 ~/.deputy/jobs/*.json 与 logs/*.log 取数并投影成面板载荷；客户端 client.js 只负责渲染
面板类目副将 → Active → Attention → Recent → 公告板（默认选中副将；点击分栏切换，同一时刻只渲染被选中那一类）
每张副将卡下面那一行符合✅/❌/❓ · 进度 已跑 Nm Ns · ETA — · 停滞 Ns —— 由只读工具 bin/deputy_conform.py 三态判定（判据只取该单卡面自己写的 acceptance 与 whitelist）
符合度三态含义✅conform＝卡面 acceptance 绿证在位且产物齐；❌deviate＝有白名单外改动（现应扣除 owner_claims 具名认领项与本单框架运行态件）；❓undecidable＝半写态/作废/未知状态（fail-closed，不猜）
ETA 为什么恒为「—」引擎侧没有「完成度百分比」字段（bin/deputy_health.py 只出 elapsed_sec / rate_bpm / budget_sec / whitelist_bytes 等）⇒ 按「算不出就留 — 但须具名说明」处理，未编造数字
白忙预警进度在动（rate_bpm>0）且符合度不是 ✅ ⇒ 该卡标红，行的 title 给出原因
